ЗАВДАННЯ №1. Зовнішній вигляд макету. Код макету

Тип макету

Сайт TaskTracker побудовано за комбінованим типом макету: це гумовий макет (ширина контейнера й колонок задана у відсотках, flex і rem, тому блоки розтягуються за шириною екрана) разом з адаптивним (на трьох контрольних точках через медіа-запити змінюється кількість колонок, вигляд меню та розміри елементів). Максимальна ширина контейнера обмежена (max-width: 70rem), щоб рядки тексту не ставали задовгими на широких екранах.

ФіксованийШирина задана в пікселяхПовний контроль над виглядом, проста версткаГоризонтальна прокрутка на вузьких екранах, порожні поля на широких

КомбінованийПоєднує гумовий, еластичний і адаптивний підходиГнучкий і зручний на всіх пристрояхСкладніший у розробці та підтримці

Зовнішній вигляд макету

Схема макету для трьох типів пристроїв:

Особливості макету (що пояснити викладачу)

  • Усі елементи розташовано в потоці; рядки й колонки будуються контейнерами display: flex (шапка, сітка карток, дві колонки «Про сервіс» і «Форма», підвал).
  • Картки мають flex: 1 1 15rem: у рядок їх вміщується стільки, скільки дозволяє ширина (4, 2 або 1), решта переноситься завдяки flex-wrap: wrap.
  • Три контрольні точки: понад 1024 px — десктоп, 701–1024 px — планшет, до 700 px — мобільний пристрій.
  • На мобільному навігація перетворюється на «бургер-меню», яке плавно розкривається (max-height і opacity).
  • Таблиця й карта зображення обгорнуті в блок з overflow-x: auto, тому на вузькому екрані прокручуються всередині блока, а сторінка не розширюється.

Семантичні компоненти інтерфейсу

  • <header> — логотип, навігаційне меню, кнопка-бургер і вступний блок;
  • <main> — картки можливостей, таблиця завдань, розділи «Про сервіс» і «Нове завдання»;
  • <footer> — довідкова й контактна інформація.

/* TaskTracker. ЛР №3 — бургер-меню для малих екранів */
(function () {
  var burger = document.getElementById('burger');
  var menu = document.getElementById('menu');
  if (!burger || !menu) return;

  function setOpen(open) {
    menu.classList.toggle('open', open);
    burger.setAttribute('aria-expanded', String(open));
    burger.setAttribute('aria-label', open ? 'Закрити меню' : 'Відкрити меню');
  }

  burger.addEventListener('click', function () {
    setOpen(!menu.classList.contains('open'));
  });
  menu.addEventListener('click', function (e) {
    if (e.target.tagName === 'A') setOpen(false);
  });
  document.addEventListener('keydown', function (e) {
    if (e.key === 'Escape') setOpen(false);
  });
  window.addEventListener('resize', function () {
    if (window.innerWidth > 700) setOpen(false);
  });
})();

Адаптивна верстка: десктопна, планшетна та мобільна версії

Десктопна версія (понад 1024 px)

Базові стилі без медіа-запиту. Контейнер займає 90% ширини, але не більше 70rem. Меню в один ряд праворуч від логотипа. Чотири картки в ряд (flex: 1 1 15rem), «Про сервіс» і форма стоять у двох колонках, підвал має чотири колонки.

Планшетна версія (701–1024 px)

Діє запит @media only screen and (min-width: 701px) and (max-width: 1024px). Контейнер розширюється до 94%, картки займають по половині ширини (calc(50% - 1rem)), блок «Про сервіс» і форма розташовуються одна під одною (flex-direction: column), меню переноситься на два рядки.

Мобільна версія (до 700 px)

Діє запит @media (max-width: 700px). Меню ховається, з’являється кнопка-бургер, а посилання розкриваються плавно (transition: max-height .35s, opacity .3s). Картки йдуть в одну колонку, колонки «Про сервіс» і форми стають вертикальними, підвал має одну колонку.

Метатег viewport

<meta name="viewport" content="width=device-width, initial-scale=1.0"> повідомляє мобільному браузеру, що ширина області перегляду дорівнює ширині пристрою, а початковий масштаб становить 100%. Без нього телефон відображав би сторінку як десктопну й зменшував її, і медіа-запити працювали б неправильно.

ЗАВДАННЯ №2. Верстка таблицями та плаваючими блоками

Номер варіанта дорівнює останній цифрі номера у списку групи (19): варіант 9 для табличної верстки та варіант 10 (9 + 1) для верстки плаваючими блоками. Нумерація блоків відповідає макетам із завдання: 1 — шапка, 2 — ліва колонка, 3 — підвал, 4 — основний вміст.

ВерсткаВаріантФіксованаГумова
Таблична9ширина таблиці й стовпців у pxширина таблиці й стовпців у %
Блокова (float)10ширина блоків у pxширина блоків у %

Табличний макет

Сторінку розбивають на комірки таблиці <table>. Об’єднання комірок (rowspan, colspan) дозволяє отримати складну структуру. Простота верстки та однакова поведінка в усіх браузерах — його переваги, а недоліки: розмітка не відображає змісту, код громіздкий, сторінка повільніше відображається й погано адаптується.

Блоковий макет із плаваючими елементами

Сторінку будують із блоків <div>. Властивість float: left виводить блок із потоку та притискає до краю, а решта вмісту обтікає його. Ширину колонок задають width, а батьківський елемент має overflow: hidden, щоб обгорнути плаваючі діти. Така верстка легша й чистіша за табличну, але вимагає зайвих хитрощів для колонок однакової висоти.

Нижче в меню — чотири сторінки із кодом, скріншотами та поясненнями.

Основні поняття flexbox

Flexbox — одновимірна модель розташування: елементи вишиковуються вздовж головної осі (flex-direction), а поперек неї діє поперечна вісь. Контейнер задають display: flex, а його дітей налаштовують окремими властивостями.

ВластивістьДе застосовано на сторінціПризначення
display: flex.product, .products, .footer-inner, .trust liробить елемент flex-контейнером
flex-direction: column.product-info, .trust, .itemрозташовує елементи вертикально
flex-wrap: wrap.product, .products, .footer-innerпереносить елементи на новий рядок, коли вони не вміщуються
flex: 1 1 22rem.product-image, .product-info, .item, .colскорочення для grow, shrink і basis: блок може розтягуватись і стискатись від базової ширини
gapусі flex-контейнеривідстань між елементами
justify-content.footer-inner, .buyвирівнювання вздовж головної осі
align-items.price, .trust li, .noteвирівнювання поперек головної осі
align-self.buy-smallіндивідуальне вирівнювання одного елемента

Особливості макету

  • Двоколонковий блок товару: зображення зліва та інформація справа, кожен займає не менше 22rem; на вузькому екрані колонки автоматично стають одна під одною.
  • Картки «Схожих товарів» (4 в ряд, потім 2, потім 1) — flex-рядок із переносом.
  • Підвал — flex-рядок із чотирьох колонок; на телефоні вони йдуть стовпчиком.
  • Для адаптивності є два медіа-запити (до 700 px та до 420 px), розміри задано в rem і відсотках.
  • Зображення — власні SVG-ілюстрації з папки lab3/images.
